# Helm Charts (mops-charts)

## Library Chart Pattern

Shared library charts provide reusable Kubernetes templates. App charts
depend on them and supply values.

```
mops-charts/charts/
  ├── mds-base/          ← Library: Deployments, Services, Routes, ConfigMaps
  ├── secrets-base/      ← Library: ExternalSecrets (Doppler, AWS SM)
  ├── sine-api/          ← App chart (depends on mds-base)
  ├── schema-registry/   ← App chart (depends on mds-base + secrets-base)
  ├── codec/             ← App chart
  ├── commands/          ← App chart
  └── ...
```

## Multi-Service Pattern

A single chart deploys multiple services by aliasing the library:

```yaml
# Chart.yaml
dependencies:
  - name: mds-base
    version: "1.0.0"
    repository: https://artifactory.int.vastspace.com/vast-helm
    alias: server
  - name: mds-base
    version: "1.0.0"
    alias: worker
  - name: mds-base
    version: "1.0.0"
    alias: migration
```

Each alias gets its own values block (`server:`, `worker:`, `migration:`).

## Built-in Integrations

`mds-base` has first-class support for:

| Integration | Enable with | Generated |
|-------------|-------------|-----------|
| **Kafka** | `application.kafka.enabled: true` | Consumer/producer config in ConfigMap |
| **PostgreSQL** | `application.postgres.enabled: true` | Write + read replica connection strings |
| **Redis Sentinel** | `application.redis.enabled: true` | Sentinel connection config |
| **Gateway API** | `listenerSet` / `httpRoute` / `grpcRoute` | ListenerSet, HTTPRoute, GRPCRoute resources |

## Versioning

All charts use semver (`MAJOR.MINOR.PATCH`):

- **Library charts** (`mds-base`): Breaking → MAJOR, features → MINOR, fixes → PATCH
- **App charts**: Start at `0.1.0`, version reflects app changes

Charts publish to Artifactory automatically on merge to main when
`Chart.yaml` version changes. RC builds (`v1.2.0-rc.1`) can be published
manually via GitHub Actions without creating git tags.

Git tags follow `<chartname>/v<version>` (e.g., `mds-base/v1.1.0`).

## Updating a Chart

1. Make changes in `mops-charts/charts/<chart>/`
2. Bump version in `Chart.yaml`
3. Update `CHANGELOG.md` for library charts
4. `helm lint -f linter_values.yaml` locally
5. Open PR. CI validates. Merge.
6. Consumers: update dependency version in their `Chart.yaml`, run
   `helm dependency update`, commit `Chart.lock`

## Local Development

For rapid iteration, temporarily use `file://` references (never commit):

```yaml
dependencies:
  - name: mds-base
    version: 0.0.0
    repository: file://../../charts/mds-base
```

## Key Files

| File | Purpose |
|------|---------|
| `Chart.yaml` | Name, version, dependencies |
| `Chart.lock` | Pinned dependency versions (always commit) |
| `values.yaml` | Default values |
| `linter_values.yaml` | Minimal values for `helm lint` CI |
| `CHANGELOG.md` | Version history (library charts) |
| `README.md` | Auto-generated by `helm-docs` (do not edit) |
